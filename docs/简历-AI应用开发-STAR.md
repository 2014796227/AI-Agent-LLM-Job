### 经历 1 · 技术选型与架构决策

- **【S 情境】** 立项一个覆盖 AI 应用岗核心关键词（Multi-Agent/RAG/Function Calling/评测）的作品项目，第一个重大决策是编排框架选型——LangGraph/CrewAI 开箱即用，但过程黑盒与"面试深挖讲不清"的风险并存。
- **【T 任务】** 在"生态成熟度"与"每一行可解释"之间做出并论证架构决策，建立全部组件的选型依据。
- **【A 行动】** 拍板**自研轻量编排内核**（决策记录 ADR-0001，决策人署名）；作为八篇 ADR 的决策人完成全部选型拍板：pgvector 而非专用向量库（同库事务一致性）、hfq 后复权全链路信号口径、回测 fill→shift 显式契约、单机 Compose 部署形态等；主持蓝图多轮评审——**在第四轮评审中发现 v7 版本 hfq 论证错误**（后复权历史不因未来除权变化），推动修正并沉淀为 ADR-0003 的正式决策（版本史留痕）。
- **【R 结果】** 形成全部 8 篇署名 ADR；自研内核在后续 15+ 次真实缺陷中被逐行定位修复（框架黑盒风险被实证规避）；hfq 口径经 M0 实测验证（261 重叠日×10 列逐日一致）。

### 经历 2 · 验收体系设计与执行（质量的最终责任人）

- **【S 情境】** 工程实现采用 AI 编码协作模式——效率极高，但"AI 生成代码的质量风险"成为项目最大风险源。
- **【T 任务】** 以最终责任人的身份设计并监督执行一套验收体系，保证系统达到可上线质量。
- **【A 行动】** 设计七轮里程碑验收（M0 事实核验→M6 收尾），逐项核对证据后签收；拍板评测集设计（46 用例：确定性断言/LLM 裁判/人工抽查三层）；验收中发现的缺陷逐条登记问题区并驱动修复——包括否决"评测器裸崩"类修复方案、要求"非法 spec 应记为用例失败而非崩溃"的正确语义；确认评测集与方法论语料（120 条）终稿（"全部通过"拍板留痕）。
- **【R 结果】** 终版评测 **46 用例 0 失败**：回测三元组复算 **10/10 全真**（1e-9 容差）、报告数字一致性 8/8、RAG 引用命中 15/17、正确拒绝 5/8（缺陷如实记录不粉饰）；备份恢复演练**零悬空**、限流验证通过（20 次/时、第 21 次拒绝）。

### 经历 3 · 上线后真实使用测试与缺陷发现（第一用户）

- **【S 情境】** 系统上线后进入真实使用阶段，需要以真实用户视角验证全链路——这是任何内部测试替代不了的环节。
- **【T 任务】** 作为第一用户执行端到端使用测试，发现问题、定位根因、驱动修复并验收。
- **【A 行动】** 通过真实提问先后发现 4 类线上问题：**任务完成但报告为空**（复盘为 PM-001 事故：critic 连续打回 + writer 空输出无防御）、**ETF 标的数据获取失败**（交易所代码段误判 + 数据源不覆盖基金段）、**免费层限流导致任务失败无解释**、**降级任务无部分结果**；对后两项明确提出产品要求——"失败原因要在前端显示出来让人知道为什么失败、失败后应该怎样做"与"在前端添加数据来源标识方便核查数据真实性"（两句话即 v35 失败可解释面板与 v36 数据溯源面板的需求来源，会话留痕）；每次修复均要求线上复验后才确认关闭。
- **【R 结果】** 驱动 6 轮线上迭代（数据双源回退/ETF 支持/失败可解释/数据溯源/降级兜底）全部闭环验证；数据溯源面板成为演示时的信任抓手（来源/行数/拉取时间可用行情 App 当场核对）。

### 经历 4 · 知识库语料策展与审核（RAG 可信度的源头）

- **【S 情境】** RAG 系统的可信度取决于语料——AI 生成的语料若不审核，引用再准也是"垃圾进垃圾出"。
- **【T 任务】** 建设一个 100% 可溯源的知识库：官方披露文件 + 人工审核的策展内容。
- **【A 行动】** 拍板语料范围（巨潮年报节选 5~10 份 + 量化方法论 100~200 条，PRD 决策 #4）；**逐条审核 120 条 AI 初稿方法论并全部批准**（生产库标注"AI 初稿·人工审核通过"）；验收引用链路——要求年报数字必须能点开官方 PDF 原页核对。
- **【R 结果】** 4 份语料上线（年报节选×3 official + 方法论 120 条 curated，DB 存巨潮原始 URL）；线上验证：知识问答报告 13 处引用横跨双文档、引用页渲染 200 PNG；评测引用断言 15/17。

### 经历 5 · 部署、成本与运维决策

- **【S 情境】** 项目需以零/极低成本上线公网演示，且面向国内访问。
- **【T 任务】** 在零 API 预算约束下完成部署选型、资源准备与运维制度建立。
- **【A 行动】** 部署形态决策：评估并**否决 Vercel（serverless 与长任务架构冲突）与 Render（付费+国内访问不稳）**，选定新加坡轻量服务器 + Docker Compose（免备案、国内直连）；成本决策：全免费模型策略（智谱 flash 免费层 + 硅基 bge-m3 免费 embedding，三层回退链）并引入第二家 API 补齐向量检索；资源准备（服务器采购、双 API 密钥）；验收安全检查单（外部 admin/metrics 403、密钥文件权限、备份 cron 每日 04:00）与备份恢复演练。
- **【R 结果】** 系统以**约 ¥24/月服务器成本 + ¥0 API 成本**上线运行至今（healthz 可查）；备份链生产真跑（dump 恢复计数一致 + 卷零悬空对账 7/7）。

- **【A 行动】** 通过结构化需求访谈完成 **16 项产品决策**并逐项拍板：定位（如实产品能力演示）、第一用户（投资新手）、第一痛点（研究效率）、核心主张（可信优先）、MVP 三件套、Roadmap（P1 新手教育模式）、做减法（术语白话化）、四项边界口径、北极星指标（复访/复用率）、埋点优先级、A/B 实验设计（风险提示位置）、指标分层（对内效率/对外信任）；另完成 PRD 五项关键决策拍板（回测成交口径 next_close、引用无鉴权等）。
- **【R 结果】** 产品文档完整成册（背景/用户/痛点/优先级/流程图/边界/埋点方案，`docs/pm/产品文档.md`）；工程侧据此实现的"可信主张"界面（溯源面板+失败可解释+引用原页）成为项目差异化标识。

### 经历 7 · AI 协作开发工作流（AI 应用开发的元实践）

- **【S 情境】** 一人无团队交付生产级 AI 应用，必须回答"如何让 AI 编码可控、可验收、可追溯"。
- **【T 任务】** 建立一套可审计的 AI 协作开发流程，而非"许愿式提示词"。
- **【A 行动】** 确立**蓝图为唯一代码权威**（37 个版本决策修复史，每次变更含根因与验证）；建立"验证驱动修复"纪律——要求每个修复配结构断言/单测回归/线上复验（该纪律曾当场抓住机械同步误删 400 行的事故）；建立真实事故复盘制度（PM-001：时间线/5-Why/证据链五项/防回归）并作为复盘主持签发。
- **【R 结果】** 15+ 真实缺陷全部定位-修复-验证-留痕闭环；AI 生成代码经 46 用例评测 + 32 单测 + 7 轮验收把关——**"用 AI Agent 工作流交付 AI 产品"本身就是该岗位工作方式的实证**。
