## 2. 根因分析（5 Why，写到机制层）

1. 为什么用户看不到报告？→ done 任务的 report 字段为空串。
2. 为什么 report 为空？→ `_execute` 末尾 `context["_report"] = draft`，而 draft 在最后一轮 revise 后是空串——writer 模型（免费层 flash）在"无数据 + critic 连续打回"压力下返回了**空 content**。
3. 为什么空 content 会成为最终报告？→ 修订循环 `draft = rw.text` 无空值防御；writer 初稿也非空，问题特定于"revise 返回空"这一路径。
4. 为什么上线前没发现？→ 该路径需要同时满足：行情源不可用 + 知识库为空 + critic 连续 revise + flash 恰好输出空——M0 端到端复验时四条件从未同时成立；单测不覆盖 orchestrator 的 critic 循环（依赖真实 LLM）。
5. 为什么单测不覆盖？→ 编排循环的 LLM 行为依赖真实模型输出，项目测试策略（蓝图 Part 9）聚焦确定性内核（DSL/回测/事件流/切块）——这是**已知取舍**，代价由线上首类问题暴露。防回归措施见 §4。

**放大因素**：同日东财对服务器 IP 的累计限流（M2 #3）大幅提高了"行情不可用"概率，使原本低概率的四条件组合成真。
