# ADR-0002：GLM 模型分工与双层 token 预算

- 状态：已接受
- 日期：2026-08-15
- 决策人：＿＿＿＿（待签名）
- 关联：蓝图 config.py / budget.py / tasks.py(reserve_daily)

## 背景

约束：仅智谱 GLM API 可用；演示系统面向公网访客，费用必须可控；模型能力分层明显（GLM-4.6 旗舰 vs GLM-4.7-Flash 免费）。

## 决策

1. **模型分工**：Supervisor/Writer/Critic 用 GLM-4.6（规划、成稿、审查需深度推理）；research/strategy 用 GLM-4.7-Flash（工具调用与摘要，免费）；评测裁判用 Flash；任意入口失败自动降级到 fallback_model
2. **双层预算**：
   - 单任务：DAG≤6 节点、LLM≤25 次、工具≤40 次、token≤120k、墙钟 300s（deadline 协作检查 + wait_for 硬上限）；超限**优雅降级**为带"预算耗尽"标注的部分结果
   - 每日：预留式 2M token（reserve_daily 原子 SQL 预占，任务结束释放实际消耗；释放权归状态迁移方）

## 理由

- 成本结构：大部分调用（工具循环、裁判）落在免费模型上，付费调用集中在关键推理——演示期 API 成本预计 ¥10~50/月
- 预算默认值的估算依据：各 AgentSpec 典型步数（≤6）× 节点上限 6 + critic 2 轮 < 25 次 LLM 上限；120k token ≈ 25 次 × 平均 4k + 余量
- 预留式而非事后统计：公网并发提交不能击穿日预算（第五轮审计 P0-10 的教训）

## 后果与妥协

- 单任务 120k 预留意味着日预算 2M 下并发在飞任务上限约 16 个——对演示规模足够，指标（usage_day）可观测
- degrade 产出是"部分结果+标注"，不是完整报告——这是产品边界而非缺陷，前端如实展示
