## 决策 1：数据源 = AKShare 包在数据访问层后

生产对应 Wind/聚望/自建；本项目以适配器模式封装（MarketDataSource：重试/列 schema 校验/缓存版本键），生产可换实现。理由：零预算约束 + 架构隔离让"数据源不稳定"成为可管理风险（校验让失效早发现，缓存兜底并标注来源）。

## 决策 2：计算口径 hfq 全链路，展示口径 raw

**推导**（回应第四轮评审的质疑，结论修正了 v7 的含混表述）：
- 后复权标准定义 `P_hfq[t] = P_raw[t] × ∏{f_e : 除权日 ≤ t}`——乘积只含 t 之前的事件，**数学上** hfq 历史价格不随未来除权变化；前复权 `P_qfq[t] = P_hfq[t]/F(now)` 则全历史重缩放
- 但**不依赖该数学性质**：数据商存在因子修订/口径变更的现实风险
- 兜底（复现保证的最终来源是架构）：评测固定绝对日期窗口 + `evals/fixtures/` 冻结快照（含 fetched_at/checksum/akshare_version 元数据）；跨时间对比一律对快照复算

**信号层必须 hfq 的原因**：若信号用 raw，除权日跳空会制造假信号（如跳空触发"跌破 N 日新低"退出，实际是除权而非价格行为）。

**M0 实证（2026-08-15 已执行，结果回填）**：拉取同起点、不同末端日期的两个 hfq 窗口（600519，2023-06-01~2024-06-30 与 2023-06-01~2026-05-31），重叠段逐日比对——重叠 261 个交易日，**hfq 与 raw 全部 10 列逐日最大绝对差 = 0.0，一致** ⇒ 记录"该数据源（东财经 akshare 1.18.91，本日实测）上该性质成立"；数据商口径漂移的现实风险仍由快照机制兜底（复现契约不变）。证据：`scripts/m0_akshare_checks.py` 输出（docs/verification/M0-记录.md §4）。

## 后果与妥协

- 展示层（当前价/区间高低）用不复权原始价并标注"不复权"；净值曲线为归一化 hfq 收益（口径=引擎）
- AKShare 无 SLA：接口失效是可预期事件，处置路径=重试→缓存兜底（标注）→降级提示；真实失效事故按 provenance 规范复盘
